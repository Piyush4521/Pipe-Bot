# PipeBot Inspection and Defect REST API Specification

> **Version**: API v1  
> **Status**: Stage 2 Implementation Completed  
> **Base URL**: `http://127.0.0.1:8000/api/v1`

---

## 1. Overview and Design Principles

The PipeBot inspection and defect REST API provides structured persistence, lifecycle state supervision, anomaly recording, and operator verification for pipeline crawler inspections.

Key design principles:
- **Explicit Lifecycle Management**: Inspections follow a strict deterministic finite state machine (`created` -> `in_progress` -> `paused` -> `completed` / `cancelled`).
- **Decoupled Timestamp Semantics**: Frame capture timestamps are strictly preserved and never conflated with AI inference or record creation timestamps.
- **Genuine Odometry Storage**: Penetration distance is stored only when upstream encoder measurements exist; distance is never inferred from AI processing latency.
- **Audit-Safe Defect Lifecycle**: Anomaly detections cannot be permanently destroyed through casual operations; soft-deletion and operator review statuses (`pending`, `confirmed`, `rejected`) preserve regulatory integrity.

## 2. Controlled Enums

### 2.1. Inspection Lifecycle Status (`InspectionStatus`)

| Status | Code | Description | Allowed Next Transitions |
| :--- | :--- | :--- | :--- |
| `created` | `CREATED` | Initial session created; crawler stationary, awaiting start | `in_progress`, `cancelled` |
| `in_progress` | `IN_PROGRESS` | Crawler actively navigating conduit or recording data | `paused`, `completed`, `cancelled`, `failed` |
| `paused` | `PAUSED` | Crawler temporarily halted (e.g. clearing obstruction) | `in_progress`, `completed`, `cancelled` |
| `completed` | `COMPLETED` | Inspection run formally finalized with odometry summary | *Terminal state* |
| `failed` | `FAILED` | Session aborted due to critical hardware/pipeline fault | *Terminal state* |
| `cancelled` | `CANCELLED` | Session aborted intentionally by operator before completion | *Terminal state* |

### 2.2. PVC Conduit Defect Classifications (`DefectClass`)

The detection schema targets 4 distinct PVC conduit structural anomalies:

| Class | Identifier | Description |
| :--- | :--- | :--- |
| `deformation` | `DEFORMATION` | Cross-sectional ovality, buckling, or inward conduit collapse |
| `misalignment` | `MISALIGNMENT` | Joint displacement, angular offset, or pipe disengagement |
| `obstacle` | `OBSTACLE` | Foreign debris, silt deposit, roots, or physical conduit blockage |
| `rupture` | `RUPTURE` | Longitudinal fracture, puncture, perforation, or wall shear |

### 2.3. Defect Review Status (`DefectReviewStatus`)

| Status | Identifier | Compatible Frontend Alias | Description |
| :--- | :--- | :--- | :--- |
| `pending` | `PENDING` | `unreviewed` | Newly detected anomaly awaiting operator verification |
| `confirmed` | `CONFIRMED` | `verified` | Operator confirmed anomaly as genuine pipeline defect |
| `rejected` | `REJECTED` | `dismissed` | Operator reviewed detection and ruled it a false positive |

## 3. Timestamp and Odometry Semantics

PipeBot enforces strict separation between three distinct temporal concepts:

1. **Frame Capture Timestamp (`captureTimestamp` / `frame_capture_timestamp`)**: Recorded frame capture time generated by the ESP32-CAM optical module when a video frame is acquired (not a verified physical shutter synchronization signal).
2. **AI Inference Timestamp (`inferenceTimestamp`)**: UTC timestamp recorded when the server-side YOLO neural network evaluates the image frame and generates bounding boxes.
3. **Record Audit Timestamps (`createdAt`, `updatedAt`)**: Database transaction timestamps generated by the backend.

### UTC Normalization Strategy
SQLite does not natively store timezone offsets. To prevent timezone ambiguity:
- All timestamps written to or read from the database utilize the `UtcDateTime` SQLAlchemy TypeDecorator, which enforces `tzinfo=timezone.utc`.
- Incoming timestamps with timezone offsets (e.g. `+05:30` or `-04:00`) are converted mathematically to UTC.
- Naive timestamps without offset are explicitly interpreted as UTC per system policy, preventing silent corruption from local server clocks.
- All API responses serialize timestamps to standardized ISO 8601 UTC strings with a trailing `Z`.

### Odometry Correlation Rule
Defect penetration distance (`estimatedDistanceMeters`) is correlated strictly from rotary encoder counts associated with the recorded frame capture time. The backend never computes defect position from inference completion time. When encoder telemetry is absent, `estimatedDistanceMeters` remains `null`.

## 4. Bounding Box Coordinate Convention

Bounding boxes are represented using the `BoundingBoxSchema`:

```json
{
  "x": 0.25,
  "y": 0.30,
  "width": 0.15,
  "height": 0.20
}
```

- **Origin `(x, y)`**: Represents the top-left corner of the bounding box.
- **Dimensions `(width, height)`**: Horizontal width and vertical height.
- **Normalization**: Floats representing fraction of total frame dimensions (0.0 to 1.0) or absolute pixel measurements.
- **Frontend Compatibility**: The API automatically accepts and transforms the legacy frontend format `{"xMin", "yMin", "xMax", "yMax"}`.

## 5. Inspection REST Endpoints

### 5.1. Create Inspection Session

- **Method**: `POST`
- **Path**: `/api/v1/inspections`
- **Status**: `201 Created`

#### Request Payload
```json
{
  "pipeIdentifier": "PVC-MAIN-001",
  "pipeMaterial": "PVC",
  "pipeDiameterMm": 200,
  "operatorId": "TECH-042",
  "notes": "East trunk baseline inspection"
}
```

#### Response (201 Created)
```json
{
  "pipeIdentifier": "PVC-MAIN-001",
  "pipeMaterial": "PVC",
  "pipeDiameterMm": 200,
  "operatorId": "TECH-042",
  "notes": "East trunk baseline inspection",
  "id": 1,
  "inspectionId": "INSP-20261030-9F5A7F",
  "status": "created",
  "startedAt": null,
  "completedAt": null,
  "totalDistanceMeters": null,
  "defectCount": 0,
  "createdAt": "2026-10-30T15:31:22.645918Z",
  "updatedAt": "2026-10-30T15:31:22.645927Z"
}
```

---

### 5.2. List Inspection Sessions

- **Method**: `GET`
- **Path**: `/api/v1/inspections`
- **Query Parameters**:
  - `limit` (int, default 50, max 100): Page size.
  - `offset` (int, default 0): Records to skip.
  - `status` (string, optional): Filter by `created`, `in_progress`, `paused`, `completed`, `failed`, `cancelled`.
- **Status**: `200 OK`

#### Response (200 OK)
```json
{
  "items": [
    {
      "pipeIdentifier": "PVC-MAIN-001",
      "pipeMaterial": "PVC",
      "pipeDiameterMm": 200,
      "operatorId": "TECH-042",
      "notes": "East trunk baseline inspection",
      "id": 1,
      "inspectionId": "INSP-20261030-9F5A7F",
      "status": "in_progress",
      "startedAt": "2026-10-30T15:31:30.925330Z",
      "completedAt": null,
      "totalDistanceMeters": null,
      "defectCount": 1,
      "createdAt": "2026-10-30T15:31:22.645918Z",
      "updatedAt": "2026-10-30T15:31:30.927268Z"
    }
  ],
  "total": 1,
  "limit": 50,
  "offset": 0
}
```

---

### 5.3. Retrieve Single Inspection Session

- **Method**: `GET`
- **Path**: `/api/v1/inspections/{inspection_id}`
- **Path Parameter**: `inspection_id` (either public `INSP-...` string or integer database ID)
- **Status**: `200 OK` (or `404 Not Found`)

---

### 5.4. Update Inspection Metadata

- **Method**: `PATCH`
- **Path**: `/api/v1/inspections/{inspection_id}`
- **Status**: `200 OK`

#### Request Payload
```json
{
  "pipeIdentifier": "PVC-MAIN-001-REV",
  "notes": "Re-calibrated optical focus"
}
```

---

### 5.5. Start Inspection Session

- **Method**: `POST`
- **Path**: `/api/v1/inspections/{inspection_id}/start`
- **Description**: Transitions status from `created` to `in_progress` and records UTC `startedAt`.
- **Status**: `200 OK` (or `409 Conflict` if invalid state)

---

### 5.6. Pause Inspection Session

- **Method**: `POST`
- **Path**: `/api/v1/inspections/{inspection_id}/pause`
- **Description**: Transitions status from `in_progress` to `paused`.
- **Status**: `200 OK` (or `409 Conflict`)

---

### 5.7. Complete Inspection Session

- **Method**: `POST`
- **Path**: `/api/v1/inspections/{inspection_id}/complete`
- **Description**: Transitions status from `in_progress` or `paused` to `completed`.
- **Status**: `200 OK` (or `409 Conflict`)

#### Request Payload (Optional)
```json
{
  "totalDistanceMeters": 42.18,
  "notes": "Completed full run to junction box"
}
```

---

### 5.8. Cancel Inspection Session

- **Method**: `POST`
- **Path**: `/api/v1/inspections/{inspection_id}/cancel`
- **Description**: Cancels session before completion.
- **Status**: `200 OK` (or `409 Conflict`)

---

### 5.9. Archive Inspection Session

- **Method**: `POST`
- **Path**: `/api/v1/inspections/{inspection_id}/archive`
- **Description**: Safely archives an inspection session (`is_archived = true`) without destroying associated defect evidence.
- **Status**: `200 OK`

---

### 5.10. Reject Permanent Deletion

- **Method**: `DELETE`
- **Path**: `/api/v1/inspections/{inspection_id}`
- **Description**: Permanent inspection deletion is strictly rejected to preserve regulatory compliance records.
- **Status**: `409 Conflict`

---

### 5.11. List Inspection Defects

- **Method**: `GET`
- **Path**: `/api/v1/inspections/{inspection_id}/defects`
- **Query Parameters**: `limit`, `offset`
- **Status**: `200 OK`

### 6.2. List Defect Detections

- **Method**: `GET`
- **Path**: `/api/v1/defects`
- **Query Parameters**:
  - `limit` (int, default 50): Items per page.
  - `offset` (int, default 0): Items to skip.
  - `inspection_id` (string, optional): Filter by inspection identifier.
  - `class` (string, optional): Filter by class (`deformation`, `misalignment`, `obstacle`, `rupture`).

### 6.4. Update Defect Review Status

- **Method**: `PATCH`
- **Path**: `/api/v1/defects/{defect_id}/review`
- **Status**: `200 OK`

#### Request Payload
```json
{
  "status": "confirmed",
  "notes": "Verified joint shear defect by senior engineer"
}
```

*Note*: Also accepts frontend aliases:
- `"verified"` maps to `"confirmed"`
- `"unreviewed"` maps to `"pending"`
- `"dismissed"` maps to `"rejected"`

---

### 6.5. Soft-Delete Defect Detection

- **Method**: `DELETE`
- **Path**: `/api/v1/defects/{defect_id}`
- **Description**: Sets `is_deleted = true`, omitting the record from regular query listings while maintaining regulatory compliance audit logs.
- **Status**: `200 OK`

## 7. Error Response Format

All error responses return standardized structured JSON:

```json
{
  "error": "Not Found",
  "message": "Inspection with identifier 'INSP-UNKNOWN' was not found.",
  "details": {
    "resource_type": "Inspection",
    "resource_id": "INSP-UNKNOWN"
  }
}
```

### Standard Status Codes
- `200 OK`: Successful retrieval or state update.
- `201 Created`: Resource successfully created.
- `400 Bad Request`: Generic domain error.
- `404 Not Found`: Target entity does not exist.
- `409 Conflict`: Invalid lifecycle state transition or duplicate identifier.
- `422 Unprocessable Entity`: Input payload validation failure.
- `500 Internal Server Error`: Unhandled server exception (stack trace sanitized).
